## Still open

Wording risks, most important first, each with the smallest fix. Each passed here because the reader filled the gap with judgment.

1. **The confirmed-prospect rerun asks again.** `tracker-schema.md`, "Rejections, safely": "On yes, or 'you pick,' mark that row ... Run the rejection snippet with `include_prospects = True`." Rerun with the role the user named, as the line reads, the snippet prints `THE EMAIL NAMES 'PM', NO EXACT MATCH. WHICH ONE? ask the user: [('Program Manager', 'prospect', '')]` and writes nothing, so a literal reading asks the user a second time about the row they just confirmed (measured in case 2; safe, but clumsy). I set `role = "Program Manager"` and it went through. `PM_MEANS = None` makes this path more common: any rejection "for the PM role" is a named role with no exact match. Fix: "Run the rejection snippet with `include_prospects = True` and `role` set to that row's title."
2. **Step 8's skip offer and the new no-offer line.** `evaluate-role` Step 8: "Not in the tracker yet: offer once to add it, as `prospect` (or `skipped` if the verdict was skip and the user agrees)," against "A skip at the gate ends with no offer." Both readers picked the newer line, so a gated role never reaches the tracker. That's harmless (a scan excludes a below-floor range anyway), but the two lines still disagree on paper. Fix: add "(not after a gate skip; see Ending a reply)" to the Step 8 line.
3. **`SAME_FUNCTION` is set only in a code comment.** `contacts/SKILL.md` step 2 says "Run the import" and doesn't mention it; the instruction is the comment "set these from the user's target function," above a default that tags any "product manager" or "pm" title `same-role`. Both readers found it, but a reader who ran the block as written would tag Priya, a product manager, as Jordan's peer. Fix, in step 2: "Set `SAME_FUNCTION` to the user's own function first; the default is product management." Whether a program manager is `same-role` for a project manager isn't said; both readers left it out.
4. **"Looks at" could be read from the tracker.** `tracker-schema.md`: "Set `PM_MEANS` ... from the profile's target titles ... or `None` if the user looks at more than one kind of PM role." Jordan's tracker holds a Program Manager prospect; both readers went by the target titles, as the sentence begins. A reader who counted tracker rows would choose `None`, which only costs a question, so it's low risk. Fix: "or `None` if the target titles include more than one kind of PM role."
5. **The gated `fit-check.md` body.** Step 8 fixes only its second line. Both readers added a short "why it stopped" section (one listed the checks it passed), which a later "score it anyway" replaced. Fine as is; if a fixed shape matters, one line in Step 8 would set it.

Closed from run 9's list: the heads-up line now fits a copy from the company's own page (item 1), the Posting 2 anchor points to the exception (item 2), offers after the gate are ruled out (item 3), and the gate's parenthetical names a range below the floor (item 4, first part).
