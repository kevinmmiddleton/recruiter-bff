# Run 7: the final simulation, after Kevin's Cowork test (2026-10-16)

Run 7 checked the Phase 3 fixes: the 17-item list from Kevin's live Cowork test of `1.0.0-rc.2` (Oct 14 to 16), minus the deferred "seen before" list for scans. In each part, an agent played Claude in Cowork with the plugin installed, followed the skills as written, wrote every file into a sample folder, and graded itself strictly against written expectations. The job seeker is Sam Okafor, the same fictional persona as runs 1 to 6. No browser, no web, and no multiple-choice question tool anywhere; one part had a simulated scheduled-tasks tool that returned fixed results, and the rest had none.

## What held

- **Upgrades:** a read-only question on a 0.4 folder renamed nothing; the first write renamed all four files and named each one, contents byte-identical. In the hand-made folder it asked before renaming (listing old and new names, and warning that the planning note points at them), renamed nothing after Sam said keep them, asked which of three resumes was the primary, left all three unchanged, kept Sam's profile as an exact prefix of the new file with its own lines in a `## Recruiter BFF` section at the end, and wrote no "(not set yet)" next to anything Sam had written.
- **No tracker:** once Sam said they track in Notion, it recorded that and never offered a tracker again; no `job-tracker.csv` was created.
- **No folder:** no score, no files, no offer, and the connect-a-folder line.
- **Reminders:** asked the scheduler for 8:29 exactly, told Sam it came back as 8:25 and recorded 8:25; gave the exact clicks for Require this computer and Local folder; said quitting the app pauses the check-in; noticed a paused check-in the next day and said how to turn it back on.
- **Scheduled scan:** the prompt writes to Sam as "you" and tells the run to flag weak signals like contract roles and rank them lower, never cut them.
- **Setup:** no message asked more than three questions; "Currently" stayed "(not set yet)" in every run; one LinkedIn search unless a second covered a different title.
- **Fit check:** noticed the resume file had changed since its copy and offered a refresh first; said which resume it used; "If you apply" said where to lead with it (note, written answers, first conversations) every time.
- **Resume rule:** the tailor decline, the one-time why, and the alternate rules all held again.

## What changed after it

- **Upgrades:** a declined rename is recorded ("File names: kept") so nobody asks twice; a fit check in a folder with resume files but no saved copy asks which is the primary first (the Job Coach case); "more than one resume" replaces "several."
- **No tracker:** evaluate-role, find-jobs, and application-tracker now agree. With no tracker file, the one offer is "do you keep your applications somewhere else?", and a request to add a role counts as the yes to start one.
- **Resume copies:** the copy's first line records the original's last-changed date and time, so a same-day edit is caught; an updated file with the same name keeps the old copy under a dated name; a result the user states that isn't on the resume is marked "(you said; not on your resume yet)".
- **Setup:** strong signals are proposed from the resume, not asked cold; industries the user likes go under Company (a new "Industries I like" line), so they no longer make every role in those industries STRONG; the search link appears in the save message instead of taking its own turn; optional questions can wait until after the first scan; the weak and parked question is one question.
- **Reminders:** "every morning" means all seven days; a request that names the new time is the confirmation; with no scheduler, it still explains the two settings and the pause; the settings steps work for either task.
- **Examples that contradicted their rules** (from 7e): the profile template's strong-signal example no longer lists an industry on its own, and find-jobs' sample output shows a retention role with a floor heads-up as STRONG, as the rubric says. A plain "no, I don't track elsewhere" gets one offer to start a tracker.
- **Smaller:** one connect-a-folder script everywhere; the guide's "confirm who's who" line no longer assumes the reporting line; the tailor decline offers a cover note when the fit check is already done.
- **Scenario wording:** 7c's one miss was (b) "asks for the alternate after Sam says yes." With both resume files already in the folder, the new rule lists them and asks which is which up front, which is the intended behavior. The scenario now allows it.
