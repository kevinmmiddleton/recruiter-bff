## What changed after it

All before the 1.0.1 release, from the wording risks above:

- **The save offer is on the offer list.** `your-materials` "Ending a reply" item 3 now ends "after a written answer, saving it," so it can't lose to the preferences page or reminders, or become a second offer.
- **No true story, no draft.** "Nothing fits" now says: if neither the story bank nor the saved answers hold a true story for the question (a failure, say), ask the user for one instead of building one.
- **Used for is written once.** Adding a company to "Used for" now says "(if it isn't there already)."
- **The older version leaves a note.** A newer answer still replaces the older one on the user's yes, and keeps a line naming the companies that got the older version, so a later interview guide knows they read something slightly different.
- **Applying records the use, in any conversation.** `application-tracker`'s "I applied to X" now adds the company to the saved answer's "Used for" and the story's "Used in" when the user sent a saved answer.

Not rerun after these; each is a clause that makes an expectation the run already graded explicit in the skill.

## Still open

Wording risks, most important first, each with the smallest fix:

1. **The save offer isn't on the offer list.** `your-materials` says "Answers worth reusing: offer to save them in `job-search/materials/answers.md`," but "Ending a reply" item 3 only names "after setup, a first scan; after a scan, ...; after a fit check, ...; after a booked round, ...; after building the preferences page, ...". A literal reading could rank the save offer below "The preferences page." (item 5) or add it as a second offer. In (a), (d), and the cold case the preferences page or reminders were still unoffered, so the risk was live. Fix: add "after a written answer, saving it to `materials/answers.md`" to item 3 in `your-materials`.
2. **"Nothing fits" says to draft anyway.** "Nothing saved yet, or nothing fits? Draft from the resume and profile as usual." For a failure question, the resume has no true story to draft from; what stopped an invented one was the Never list and the review pass's "If the material is thin, say so and ask for specifics." Fix: add "If neither holds a true story for the question (a failure, say), ask the user for one instead."
3. **Used for can be written twice.** The format example writes "Used for: Fernhill (2026-10-21)" when the answer is saved, before it's sent, and then "When the user uses an answer, add the company to its 'Used for' line" can add it again. (b) didn't duplicate it, by judgment. It also means an answer saved but never sent still says it was used. Fix: "add the company to its 'Used for' line (if it isn't there already)."
4. **Replacing the older version loses what the last company read.** "with the newest version of a question replacing the older one once the user says yes." Had Sam saved the Northstar version in (c), `answers.md` would show Northstar's first and last lines, and the Fernhill guide reads that file as "anything the user already wrote to this company." The facts would still match, so it's small. Fix: keep a line for the replaced version, for example "Fernhill's version ended: ...", or keep the older version until that company's process ends.
5. **Recording use needs `your-materials` in the conversation.** `application-tracker`'s "I applied to X" doesn't mention Used for or Used in. In (b) the submission came right after the draft, so the rule was in context. Said days later in a new conversation, "I applied to Fernhill" would update nothing in the story bank (the guide would still find "Used for: Fernhill" in `answers.md`, so (g) would still work). Fix, outside this diff: one line in `application-tracker`'s "I applied to X": "If `materials/answers.md` has an answer written for this company, add the application to that story's Used in, as `your-materials` says."
6. **Smaller.** `your-materials` doesn't itself say a banked story needs a Reflection; it relies on "in the format in `interview-guide-engine`'s `references/story-bank-template.md`," whose field note held in the variant. The Used in style differs between the template's example ("Fernhill recruiter screen 2026-10") and its field note ("Fernhill application, 2026-10"); this run wrote "Fernhill application, 2026-10-21." The guide template's "Likely questions and answers" line ("Story bank story named if used.") doesn't mention marking a story the company has already read; the rule lives in Step 0 and the story bank's field note, and it held here.

Not tested: a 0.4 folder (`story-bank.md`) with the new rules; a user who edits the saved answer before sending it; two saved answers that both match a question; and anything in a real Cowork session.

- **Situation:** Brightloop, 2023. We shipped a streaks feature: a daily streak counter, with a push reminder if you hadn't meditated by 8pm.
- **Task:** It was my push; I argued for the feature.
- **Action:** We noticed push opt-outs climbing in week three. After five weeks we killed the reminder and kept a quieter streak on the home screen.
- **Result:** Day-30 retention didn't move, and push opt-outs went from about 4% to 7% in the first month.
- **Reflection:** Set push opt-outs as a guardrail before launch, instead of noticing them in week three.
